# dxkit 取扱説明書

## 1. 準備
1. Python 3.9 以上をインストール（`python3 --version` で確認）
2. `dx-kit` フォルダを任意の場所へコピー
3. （任意）Claude を使う場合: `export ANTHROPIC_API_KEY=あなたのキー`
   - 未設定でも動作しますが、簡易的な規則ベース判定になります

## 2. 初期設定（約半日）
### 2-1. 会社設定
`config/company.json` を編集します。
- `company_name` に社名
- `routes` を自社の部署名・担当に変更
- `escalation_keywords` に「必ず人が対応すべき語」を追加
- `roi.hourly_cost_jpy` を自社の人件費単価に

### 2-2. FAQ登録
`knowledge/` に Markdown を置きます。**見出し(`# `)ごとに1つの回答**になります。
```
# 営業時間
平日 9:00〜18:00 です。

# 返品について
...
```
質問の言い回しが近いほど、回答の精度が上がります。

## 3. 使い方
### 3-1. 問い合わせの処理
1. 問い合わせを1行1件のJSONで `inquiries.jsonl` に保存
   `{"id":"q1","from":"x@example.com","subject":"件名","body":"本文"}`
2. 実行: `python3 -m dxkit.cli triage inquiries.jsonl`
3. 画面に判定が表示されます
   - `auto` 自動返信可 / `review` 人が確認して送信 / `escalate` 担当部署が対応
4. `out/queue_auto.json` など3つのファイルに、返信案・転送先・根拠が出力されます

### 3-2. 書類の取り込み
1. 書類をテキスト化して保存（例: `請求書1.txt`）
2. 実行: `python3 -m dxkit.cli intake 請求書1.txt 請求書2.txt`
3. `out/documents.csv` をExcelで開く。`needs_review` が `yes` の行だけ原本と照合

### 3-3. 効果の確認
`python3 -m dxkit.cli roi` で、処理件数・自動解決数・削減時間・削減額が表示されます。

## 4. 推奨する導入ステップ
| 期間 | 運用 |
|---|---|
| 1〜2週目 | 全件を人が確認（`auto` も目視）。誤判定を記録 |
| 3〜4週目 | 誤りがなければ `auto` のみ自動送信、他は人が処理 |
| 以降 | FAQ追加、`min_confidence` や対象カテゴリを調整 |

## 5. 困ったとき
| 症状 | 対処 |
|---|---|
| すべて `review` になる | FAQが不足。質問に近い見出しを追加 |
| 自動にしたくない問い合わせが `auto` | `escalation_keywords` に語を追加、`min_confidence` を引き上げ |
| `engine: mock` と出る | APIキー未設定、またはAPI呼び出し失敗。キーと通信を確認 |
| CSVが文字化け | Excelの「データ→テキスト/CSVから」でUTF-8を指定 |
| 金額が空欄 | 「合計」「総額」「請求金額」の語が無い。書式を揃えるか `intake.py` の正規表現を調整 |

## 6. 運用上の注意
- 返金・クレーム・法務案件は、設定を変えない限りAIは回答しません。この設計を弱めないでください
- 個人情報を外部APIに送る前に、自社のプライバシー規程と契約条件を確認してください
- `out/audit.jsonl` は削除せず保管してください（監査・効果測定の根拠になります）
- テスト: `python3 -m unittest discover -s tests`
