# dxkit 仕様書（v0.1.0）

## 1. 目的
中小企業が少ない導入工数で、問い合わせ対応と書類入力の人件費を削減できる AI 業務自動化キット。他社へそのまま持ち込める独立パッケージとする。

## 2. 全体構成
```
dx-kit/
├── config/company.json   会社別設定（ルーティング・閾値・ROI係数）
├── knowledge/*.md        自社FAQ（見出し単位）
├── samples/              サンプル入力
├── dxkit/
│   ├── cli.py            コマンド入口
│   ├── triage.py         分類・返信案・自動/確認/エスカレーション判定
│   ├── kb.py             ナレッジ検索（文字bigram）
│   ├── llm.py            Claude API アダプタ（キー無し時はモック）
│   ├── intake.py         書類テキスト→CSV
│   ├── audit.py          監査ログ（JSONL追記）
│   ├── roi.py            削減効果試算
│   └── config.py
├── tests/test_kit.py     単体テスト（5件）
└── out/                  実行時出力（queue_*.json, documents.csv, audit.jsonl）
```
動作環境: Python 3.9 以上、標準ライブラリのみ。

## 3. 機能仕様
### 3.1 問い合わせトリアージ
- 入力: JSONL（`id, from, subject, body`）
- 処理: ① ナレッジ検索（上位2件、類似度0.15未満は除外）→ ② LLM が `category / confidence / draft` を JSON で返す → ③ 決定論ゲートが最終判定
- カテゴリ: faq, billing, refund, bug, complaint, legal, sales, general
- 判定ルール（上から順に評価）:
  1. `always_escalate_categories` に該当 → **escalate**
  2. `escalation_keywords` を含む → **escalate**
  3. 自動返信無効、または `auto_categories` 外 → **review**
  4. ナレッジ根拠なし（`require_kb_grounding` 有効時）→ **review**
  5. confidence < `min_confidence` → **review**
  6. 上記すべて通過 → **auto**
- 出力: `out/queue_auto.json`, `queue_review.json`, `queue_escalate.json`（各件に route=転送先、draft=返信案、kb=根拠）
- LLM 失敗・キー未設定時は規則ベースのモックへ自動フォールバック

### 3.2 書類取り込み
- 入力: 請求書・領収書のテキスト
- 抽出: 日付（YYYY-MM-DD に正規化）、金額（合計/総額/請求金額）、取引先（請求元/発行元/店名/取引先）
- 出力: CSV（UTF-8 BOM付き、Excel直開き可）。欠損が1つでもあれば `needs_review=yes`

### 3.3 監査ログ・ROI
- 全判断を `out/audit.jsonl` に時刻付きで追記
- ROI = 自動解決 × 手動時間 + 支援分 ×（手動−AI時間）+ 書類数 ×（手動−AI時間）、時給を掛けて金額化

## 4. 設定仕様（config/company.json）
| キー | 内容 |
|---|---|
| company_name | 社名 |
| model | 使用モデル（既定 claude-sonnet-5-5） |
| auto_reply.enabled | 自動返信の有効/無効 |
| auto_reply.min_confidence | 自動化に必要な信頼度（既定 0.8） |
| auto_reply.require_kb_grounding | FAQ根拠を必須にするか |
| auto_reply.auto_categories | 自動化を許すカテゴリ |
| always_escalate_categories | 常に人間対応のカテゴリ |
| escalation_keywords | 検出したら必ず人間へ回す語 |
| routes | カテゴリ→転送先 |
| roi.* | 1件あたり所要時間（分）、時給（円） |

## 5. 非機能要件
- 安全性: LLM出力は提案のみ。送信・確定は行わない（キュー出力まで）
- 説明可能性: 全判断の理由を記録
- 可搬性: 外部依存なし、設定とFAQの差替えのみで他社展開可
- 機密: 個人情報を外部APIへ送る場合は自社規程・契約条件の確認が必要

## 6. 既知の制約
- メール/チャットの受信・送信連携は未実装
- 書類抽出はテキスト前提（OCR/PDF抽出は別途）
- ナレッジ検索は簡易方式（日本語の言い換えに弱い）
- 日本語のみ対応
