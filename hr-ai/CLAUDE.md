# 人事・労務AI(規程Bot)プロジェクト

詳細仕様は @docs/SPEC.md。作業前に必ず読むこと。

## 絶対ルール
- AIは「下書き」と「規程の読み取り回答」まで。給与・保険料の計算、届出の提出、採否・懲戒の判断は実装しない。
- 人事評価は「根拠の整理（日報・育成・成果指標）」と「コメント下書き」までを実装する(`hrai/evaluation.py`)。**点数・ランク・評価区分・順位・昇給等の推奨・他者との比較・最終判断は実装しない**。評価データは `data/eval/`(Git管理外・社員IDで仮名化)、要配慮情報はAIへ渡す前に除外、評価文書は送信しない。
- 個人情報(氏名・住所・生年月日・給与・評価・健康・家族)をコード、テストデータ、ログ、プロンプトに入れない。テストは架空データのみ。
- エージェントは読み取り専用。送信・書き込み・削除は必ず承認ステップを通す。
- 文面の確認・承認は人、承認済み文書の送信はシステム(`hrai/sender.py`)が行う。未承認・承認後に本文変更・宛先が許可リスト外のものは送らない。
- 届出(社会保険・雇用保険・労基署等)の作成・提出は実装しない。人が行う。入社手続きの届出項目は期限管理のみで、完了は人が記録する。
- 勤怠アラートの判定は数値計算(コード)のみ。しきい値は `data/settings.json` の自社設定で、法令値をコードに埋め込まない。一括承認(`approve-all`)は固定テンプレートの社内通知に限り、応募者宛などの外部宛は1件ずつ承認する。
- 応募対応は受付返信・FAQ回答・日程候補まで。合否・評価・条件交渉は実装しない。応募者宛の送信は、応募メールの送信元アドレスにのみ可能。
- Slack連携は署名検証必須、承認者は `slack.approvers` 登録者のみ。評価関連の下書きはSlackに出さない。
- 回答は規程の原文引用つき。引用がソースの部分文字列であることをコードで検証する。見つからなければ「規程に記載がありません」。
- APIキーは環境変数。コミット・ログ出力・チャット貼り付け禁止。`.env`は`.gitignore`。
- 質問・回答・引用・承認者を`logs/`(SQLite)に記録する。
- 法令の数値や要件をプロンプトに埋め込まない。根拠は`data/regulations/`の自社規程のみ。
- モデル名は環境変数`LLM_MODEL`で差し替え可能にする(半年ごとの見直し前提)。

## 開発規約
- Python 3.12、型ヒントあり、`ruff`と`pytest`を通す。
- 変更前にテスト(`tests/eval/`の50問)を実行し、劣化があれば報告する。
- 不明点は実装前に質問する。推測で仕様を足さない。
