# 中小企業向け 人事・労務AI 仕様書(Claude Code用)

作成日: 2026-10-29 / 対象: 従業員数十名規模、専任人事なしの中小企業(仮定。着手前に確認)

## 1. 方針(結論)
自律AIエージェント単体でも完全自動でもなく、**労務SaaS + 自動化 + 読み取り専用のAI + 人の承認**のハイブリッドにする。

自動化の可否は3条件で決める。
1. 結果を計算・照合・形式チェックで機械的に検証できる
2. 間違えても取り消せる、または影響が小さい
3. 法的判断や本人への不利益(採否・評価・懲戒)を含まない

3つとも満たす → 完全自動(AIは文面生成のみ)。1つでも欠ける → AIは下書きまで、人が承認。

| 区分 | 業務例 | 方式 |
|---|---|---|
| 完全自動 | 勤怠締め前リマインド、入社書類の案内送付、CSV整形と差分チェック | ワークフロー |
| AI下書き+人が承認 | 求人票、面接質問、評価コメント案、退職チェックリスト、社内通達 | 汎用AI+承認 |
| AIが回答(読み取り専用) | 就業規則の質問対応、入社FAQ | 規程Bot |
| AIにさせない | 給与・保険料の計算、届出の提出、採否・評価・懲戒の最終判断 | 専用ソフトと人・社労士 |

## 2. 設計の4原則(参考書「AI人事」の共通の考え方)
1. AIは下書きと壁打ちまで。最終判断と責任は人間と専門家。
2. 個人情報は入れない。入れるなら匿名化・記号化し、学習利用をオフ。
3. 根拠を引用させ、記述がなければ推測せず「判断不能」と答えさせる。
4. 計算と届出は専用ソフトと e-Gov。AIは下準備(CSV整形、チェックリスト、案内文)まで。

**Claude Codeが最初に作るのはフェーズ1(規程Bot)。** フェーズ0の成果物(規程の電子データなど)が無ければ、先にそれを依頼する。

## 4. アーキテクチャ(フェーズ1〜2)
```
入口(Slack/Teams/Webフォーム/CLI)
   → router(3条件で振り分け)
        ├ 完全自動: 通知・案内・集計(LLMは文面生成のみ)
        ├ 下書き→承認: LLMが下書き → 担当者が承認/却下 → 送信・保存
        └ 規程Bot: 規程だけを根拠に回答(読み取り専用)
   専用ソフト(労務SaaS・給与・e-Gov)は人が操作。AIは下準備まで。
共通: 学習オフの法人契約 / 最小権限 / 質問と回答のログ / 半年ごとの見直し
```
推奨スタック(Claude Codeで保守しやすい構成。n8n等のGUIツールは後で必要になったら併用):
- Python 3.12、Anthropic SDK(モデル名は`LLM_MODEL`)、pydantic
- 入口: まずCLI → 次にSlack Bolt(承認ボタン含む)
- ログ: SQLite(`logs/hr_ai.db`)
- 規程データ: `data/regulations/*.md`(条番号つきでMarkdown化。個人情報を含まない)
- テスト: pytest + `tests/eval/golden.yaml`(50問)

規程が短い(数十ページ以内)間はRAGにせず、規程全文をコンテキストに載せる。大きくなってから検索を導入する。

## 5. 規程Bot仕様
| 項目 | 仕様 |
|---|---|
| 対象者 | 社員(質問者)、総務担当(ログ確認・規程更新) |
| 参照資料 | 就業規則、賃金規程、育児・介護休業規程、社内FAQ(個人情報を含まないもののみ) |
| 回答しない | 個人の給与額・評価・懲戒・休職の可否、法律相談 |
| 回答の型 | ①結論1文 ②根拠条文(規程名・条番号・原文引用) ③注意点 ④確認先 |
| 答えられないとき | 「規程に記載がありません」と明記し、担当者の連絡先を案内 |
| 権限 | 読み取りのみ。送信・編集・外部検索は不可 |
| ログ | 質問・回答・引用範囲・日時 |

**コードで強制する検証(プロンプトに頼らない)**
- 回答内の引用文が、該当する規程ファイルの部分文字列として存在するか(不一致なら回答を破棄し「記載なし」+担当者案内)
- 質問に氏名・メール・電話番号などの個人情報パターンがあれば、入力を控えるよう促し、ログにはマスクして保存
- 規程ファイルのバージョン(更新日)を回答に表示

### システムプロンプト雛形
```text
あなたは「○○株式会社」の規程問い合わせアシスタントです。
【役割】社員の質問に、添付された社内規程だけを根拠に答える。
【前提】回答は社内規程に記載された内容に限り、法令や一般論で補わない。
【形式】
1. 結論を1文
2. 根拠条文(規程名・条番号・原文をそのまま引用)
3. 注意点(例外・手続きの有無)
4. 確認先(総務担当の連絡先)
【禁止】
- 規程にないことを推測して答えない。記述がない場合は「規程に記載がありません」と答える。
- 個人の給与・評価・懲戒・健康情報には答えず、担当者へ案内する。
- 法的判断をしない。質問者が氏名や個人情報を入力した場合は、入力を控えるよう促す。
```

### 評価テスト(公開前に必須。基準値は提案、社労士レビューで調整)
| 種類 | 問数 | 合格基準 |
|---|---|---|
| 規程に答えがある質問(有給、残業、休職、給与日など) | 30 | 引用が正確で結論が一致が95%以上 |
| 規程に答えがない質問 | 10 | 全問「記載がありません」 |
| 個人情報や判断を求める質問 | 10 | 全問回答せず担当者へ案内 |

規程を更新したとき、モデルを変えたときは同じテストを再実行してから反映する。

## 6. ガードレール
**データ**: 情報を公開/社内限/機密に分け、Botに読ませるのは個人情報を含まない「社内限」まで。氏名・住所・生年月日・給与・評価コメント・健康診断・家族情報は外部AIに原則入力しない(必要なら「従業員A」「40代」に抽象化)。要配慮個人情報(病歴・宗教など)は本人の同意なく取得できない。外部AIへの個人データ入力は第三者提供に当たる可能性がある(個人情報保護委員会 2023-06-02 注意喚起)。

**ツール設定(導入前に人が確認し記録)**
- [ ] 入力データが学習に利用されない設定
- [ ] 管理者が設定を固定でき、利用ログを確認できる
- [ ] 会社指定のAIツールのみ使用、個人アカウントでの業務利用を禁止
- [ ] 退職・異動時にアカウントを停止できる

**運用**: 就業規則を変更するときは労働者代表への意見聴取と労基署への届出が必要(労基法89条・90条)。AI成果物の帰属は就業規則と秘密保持契約で明示。個人情報を入力してしまったら履歴を消すだけでなく社内に記録・報告。採用では差別につながる属性で判断させず、合否はAIに決めさせない。

**法的確認(未確認)**: 自社以外に提供して報酬を得る場合、社労士の独占業務や弁護士法の制限に触れる可能性がある。着手前に社労士・弁護士に確認する。労働基準法の大改正は2026年時点で施行時期が未確定のため、法定の数値をプロンプトに埋め込まない。

## 7. コスト(AI層のみ。為替 $1=150円、€1=165円を仮定)
- 月額: 約1.4〜2.6万円(法人AIプラン3席 $20〜25/席、ノーコード自動化 €24〜60、API従量 約1,100〜3,000円、保存 0〜2,000円)。規程Botだけなら約1万円。
- 削減効果(仮定): 対象業務 月51時間 × 削減率30〜60% × 2,500円/時間 = 月38,250〜76,500円。
- 構築工数 約80時間(約20万円相当)、回収 約3〜17か月。**削減率と業務時間は仮定。フェーズ0で実測して差し替える。**
- 料金は第三者記事ベース。発注前に公式で再確認。
